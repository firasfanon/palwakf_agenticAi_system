# المعمارية والحوكمة — Multi-Workspace Agent Capability Expansion V1

## الهدف
تحويل المساعدين المحليين إلى منصة متعددة المجالات، لا إلى مسار خاص بـPalWakf فقط، مع استمرار PalWakf تحت حوكمة أشد.

## مبدأ الفصل
1. **مساحة العمل** تعزل البيانات، الذاكرة، السجل، والسياسة.
2. **ملف السياسات** يحدد ما يمكن للوكيل تحضيره داخل تلك المساحة.
3. **القدرة** لا تمنح تنفيذًا؛ التنفيذ يحتاج تصميمًا منفصلًا ثم Apply منفصلًا ثم UAT منفصلًا.
4. المجال التجاري لا يعمل بدون `client_id` و`project_id` في أي مسار مستقبلي قابل للحفظ أو النموذج.

## ملفات السياسات
### palwakf_government / government_strict_v1
- تحضير أدلة ومراجعات وخطط فقط.
- مراجعة بشرية إلزامية.
- عدم تنفيذ أو أدوات نظام.

### personal_development / developer_controlled_v1
- جرد مستودع، تحليل شيفرة، اقتراح Patch، خطة اختبارات، مراجعة اعتماديات.
- كل المخرجات مسودات فقط.
- أي قراءة ملفات حقيقية أو تعديل أو Git يحتاج مسار تنفيذ لاحق منفصل.

### commercial_projects / client_isolated_v1
- السياق التجاري يصبح طبقتين: عميل ثم مشروع.
- لا خلط ذاكرة أو أدلة أو مخرجات بين عميل وآخر أو مشروع وآخر.
- لا يتم تحضير عمل تجاري دون تعريف العميل والمشروع.

### research_learning / research_read_prepare_v1
- جرد المصادر، تلخيص، مقارنة، تصنيف، وحزم استشهاد.
- قراءة وتحضير فقط؛ لا تنفيذ أو تعديل مشروع.

## الثوابت العالمية
لا نموذج، لا أدوات نظام، لا Git، لا تعديل ملفات، لا نشر، لا شبكة خارجية، لا وصول بين مساحات العمل، ولا اعتماد ذاتي خلال هذه المرحلة.
